# فهرس عقارات سدين — Backend

نظام بسيط بيعمل نسخة محلية (Cache) من عقارات sadin.com.sa عشان الـ WhatsApp agent
يقدر يتأكد فورًا لو طلب العميل متوفر، من غير ما يفتح الموقع في كل رسالة.

## ⚠️ نقطة مهمة قبل ما تشغّله

أنا مبنيتش الـ scraper ده وشغّلته فعليًا على sadin.com.sa (البيئة اللي بشتغل فيها
هنا معزولة عن الإنترنت العام لأسباب أمنية). يعني الكود مبني على شكل النص الظاهر
في صفحات الموقع، مش على أسماء الـ CSS classes الحقيقية.

**أول حاجة تعملها:** شغّل `node scraper.js` على جهازك أو السيرفر بتاعك، وشوف لو
البيانات طلعت صح. لو حقل معيّن طلع فاضي أو غلط، ابعتلي:
1. افتح https://sadin.com.sa/properties في المتصفح
2. اضغط يمين → "عرض مصدر الصفحة" (View Page Source)
3. انسخلي جزء من كود الكارت بتاع عقار واحد

وأنا هظبطلك الـ selectors بالظبط بدل التخمين بالـ Regex.

## التركيب

```bash
npm install
node scraper.js        # أول تشغيل — بيبني الفهرس بالكامل (ممكن ياخد كام دقيقة)
node search.js          # تجربة سريعة للبحث
```

## الملفات

- `db.js` — قاعدة بيانات SQLite محلية (`properties.db`) بتتبني تلقائي
- `scraper.js` — بيزحف على كل صفحات `/properties` (بيع/إيجار/مطلوب/مزاد) ويستخرج كل عقار
- `search.js` — الدالة اللي الـ agent هيستخدمها للبحث في الفهرس

## التحديث الدوري

الموقع بيتغيّر (عقارات جديدة، عقارات اتباعت). عايز تشغّل `scraper.js` بشكل دوري:

```bash
# مثال: تحديث كل 4 ساعات عبر cron (على Linux/Render/VPS)
0 */4 * * * cd /path/to/sadin-agent-backend && node scraper.js >> scrape.log 2>&1
```

## إزاي هيتربط بالـ WhatsApp Agent

الفكرة إن قبل ما نبعت أي رسالة لـ Claude API، الكود بيستخرج معايير الطلب من كلام
العميل (نوع العقار، المدينة، الحي، الميزانية)، يستخدم `searchProperties()` من
`search.js` عشان يجيب نتايج حقيقية، وبعدين يحطها في الـ prompt عشان Claude يرد
بمعلومات حقيقية بدل ما "يخمّن":

```js
const { searchProperties } = require('./search');

// 1) بعد ما العميل يوصف طلبه، استخرج المعايير (ممكن عن طريق سؤال Claude
//    يرجعلك JSON بالمعايير، زي اللي عملناه في البروتوتايب الأول)
const criteria = { city: 'المدينة المنورة', district: 'العريض', property_type: 'شقة', purpose: 'sale' };

// 2) دوّر في الفهرس المحلي
const matches = searchProperties(criteria);

// 3) ابعت النتايج مع رسالة العميل لـ Claude عشان يرد برد طبيعي مبني على بيانات حقيقية
const context = matches.length
  ? `عقارات متاحة فعليًا تطابق الطلب:\n${matches.map(m => `- ${m.title} (${m.url})`).join('\n')}`
  : 'مفيش عقارات متاحة حاليًا تطابق الطلب بالظبط.';
```

ده بيمنع الـ agent إنه "يهلوس" ويقول إن عندنا عقار مش موجود فعلاً — ده مهم جدًا
لثقة العميل.

## ملفات سيرفر الواتساب (جاهزة، مستنية بس مفاتيح ميتا)

- `agentBrain.js` — عقل الـ Agent: بيكلم Claude، يستخرج معايير الطلب، يتأكد من
  الفهرس المحلي قبل ما يرد بأي حاجة عن توفر عقار (عشان ميهلوسش).
- `server.js` — سيرفر Express بيستقبل رسايل واتساب عبر webhook ويرد عليها.
- `.env.example` — انسخه وسمّيه `.env` واملأ فيه المفاتيح.

### ⚠️ مهم: مفتاح Anthropic API منفصل

اللي شغّال في الشات ده (claude.ai) مفيهوش احتياج لمفتاح API — ده جزء من بيئة
الشات نفسها. لكن السيرفر بتاعك اللي هيشتغل على Render مستقل تمامًا ومحتاج
مفتاح API حقيقي بتاعك من https://console.anthropic.com (فيه استخدام مجاني
بسيط للتجربة، وبعدين بيتحاسب حسب عدد الرسايل).

### طريقة التشغيل محليًا (للتجربة قبل الرفع)

```bash
npm install
cp .env.example .env
# املأ .env بالمفاتيح
npm start
```

### الرفع على Render

1. ادخل حساب Render بتاعك (نفس اللي استخدمته في مسكن الأول)
2. اعمل New Web Service واربطه بمجلد المشروع ده (عبر GitHub أو رفع مباشر)
3. Build Command: `npm install` — Start Command: `npm start`
4. في Environment Variables، ضيف نفس المفاتيح اللي في `.env`
5. Render هيديك رابط عام زي `https://sadin-agent.onrender.com` — ده اللي
   هتحطه في إعدادات الويب هوك على لوحة ميتا (`/webhook` في الآخر)

## الخطوة اللي بعد كده

بعد ما توثيق Meta Business يخلص وتاخد التوكن ورقم الـ Phone Number ID، هنحط
القيم في `.env`، نرفع السيرفر على Render، ونربطه بلوحة ميتا كـ webhook —
وهيبدأ يرد على العملاء فعليًا.
